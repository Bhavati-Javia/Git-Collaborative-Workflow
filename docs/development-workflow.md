# Development Workflow

The project follows a Git-based collaborative development workflow.

1. A task or issue is created in GitHub Issues.
2. A developer creates a separate branch for the task.
3. The developer makes the required changes.
4. Changes are committed with meaningful commit messages.
5. The branch is pushed to GitHub.
6. A Pull Request is created for review.
7. Another contributor reviews the changes.
8. After approval, the Pull Request is merged into the main branch.
9. The branch can be deleted after merging.

This workflow helps maintain organized development and supports collaboration among team members.
